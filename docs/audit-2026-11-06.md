### Shape of the plugin (files per package)

`extension` 330 (settings, custom config, UI, symbols, 16 intentions, line markers), `generation` 261 (new model/class/pivot, 32 code generators, field providers), `eloquent` 219 (database introspection 60, meta, references, 10 inspection files, completions, factories), `blade` 219 (Livewire 80, components 31, directives 18, 15 actions, Blade X 14), `toolwindow` 164 (log viewer 101, processes 32, Laravel Cloud 23, dashboard), `packages` 137, `routing` 131, `helperCodeGeneration` 84, `integrations` 52 (MCP, terminal, database, endpoints, LLM, Docker, Qodana, git), `wizard` 48, `smartCompletions` 38.

Architecture point: the core value is a PHP **type model**. `helperCodeGeneration` writes IDE-helper-style stub files (facades, Eloquent members, macros) so the PHP engine can resolve `$user->posts()->where(...)`, and `smartCompletions` completes on those types. OpenIDEA has no PHP type resolution (Track U4), so this whole layer cannot be reproduced at any effort.

## Limitations of the audit

What this audit did and did not establish. Read it before trusting a rating.

1. **Names, not behaviour.** For the proprietary originals (all Spring plugins, JPA, Kubernetes, Flyway, Liquibase, Swagger, Dev Containers, Twig, Blade, Laravel Idea) the inventory comes from descriptor extension points and class, package and action names. No method bodies were read, so what an inspection actually checks, its message text, its severity and its false-positive behaviour are unknown. A name such as `SpringCacheableMethodCalls` tells us the topic, not the rule. Every proprietary-derived item must be specified from public documentation and observed behaviour before it is built; the decompiled output is not a spec.
2. **Counts are rough.** Descriptor tag counts were doubled by some jars appearing twice and were halved by hand in a few places; inspection counts come from `localInspection` entries only, so inspections registered programmatically or in other modules (v2 content modules) can be missing. "About 64" and "about 37" are lower bounds on registered inspections, not on checks.
3. **Source reads were targeted.** For `.ignore`, Ideolog, Quarkus, Symfony, dotenv, Laravel (free) and the Properties plugin the public or decompiled source was inspected for actions, inspections and intentions, not read end to end. Completion contributors, reference contributors, line markers and settings pages were matched at the level of the existing READMEs and `LIMITATIONS.md`, not diffed line by line.
4. **Our side is read from READMEs, manifests and tests.** I counted our problem kinds and features from `plugin.toml`, READMEs and `code:` fields. Nothing was run in the IDE; `openidea-plugin build` was not run on all plugins (the `check` step needs `dist/plugin.wasm`); tests prove logic against `MockHost`, which differs from the host (hidden files, missing-file error kind).
5. **Versions differ between original and port.** JetBrains plugins were taken at build 263.7307.x, Laravel Idea at 13.4.1.261, Quarkus Tools 2.6.1, Symfony 2026.2.314, `.ignore` 4.5.7, Ideolog master (`aa342f0`) against our port of tag 263.7307.101. Features added after our ports show as gaps; some may not exist in the versions we ported.
6. **Freemium and paid parts.** The Symfony plugin's premium parts (`pay.xml`) are not in the public repository and were not inventoried. Laravel Idea is a paid product; the audit lists features by area only and says nothing about their quality.
7. **Feasibility is API-level, not product-level.** "F" means the API allows it. It does not mean it fits the 50 ms provider budget on a large project, that the IDE requests completion on the trigger character, or that the host behaves as documented; items marked F\* carry that risk. Three behaviours should be verified in the IDE before building on them: completion on `@` in a plugin language, `definition` on `yaml` for files that are not the plugin's, and the load cost of a plugin that activates on every YAML or JS file.
8. **Extra API gaps surfaced by the feasibility check** (not in Track U): a way for one plugin to offer settings defaults to another (blocks shipping the Laravel log format from `aritti.laravel`, so it goes into `aritti.ideolog`'s own default), and a content predicate on run detectors (already in `LIMITATIONS.md` for Quarkus). Path patterns for providers are U6.
9. **Licence position.** Decompiling proprietary JetBrains jars may conflict with their licence terms; the repo's own rule (`CLAUDE.md`, porting skill) says clean-room for proprietary plugins. The user chose to proceed on 2026-11-06 and accepted that risk. Only inventories and this document were kept; no decompiled code, strings or icons are in the repo.

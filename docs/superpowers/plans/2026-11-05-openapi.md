# OpenAPI (`aritti.openapi`) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An OpenIDEA plugin for OpenAPI 3.x / Swagger 2.0 files: `$ref` completion and go-to-definition, problems for broken refs, duplicate `operationId`s and path parameters, a project-wide endpoints tool window, a Swagger UI preview beside the text, the official JSON schema for the YAML language server, and requests for the HTTP client copied to the clipboard.

**Architecture:** A Rust plugin. Every editing feature works on the YAML key paths from the repo's shared `crates/spring-text` (`config::yaml`, byte offsets), plus a text scan for `$ref` values that also catches flow style (`{ $ref: … }`). The preview is a no-code web page (`web/`) that runs vendored Swagger UI on the custom editor's document. Structural validation (required fields, types) comes from the official OpenAPI JSON schemas through a `# yaml-language-server: $schema=` modeline inserted by a code action, the same approach as `plugins/kube-explorer/src/schema.rs`. No hand-written schema checks.

**Tech Stack:** Rust 2024, `openidea-plugin` SDK tag `v0.1.37`, `spring-text` (path dependency), Swagger UI `swagger-ui-dist` 5.34.1 (Apache-2.0, vendored, unmodified). No other crates.

**Spec:** this document's Scope section (there is no separate spec). Inputs: the OpenAPI 2.0/3.0/3.1/3.2 specifications (spec.openapis.org) and the Marketplace description of `com.intellij.swagger` (FREE, closed source → clean-room).

## Review Focus

1. **A YAML file that isn't OpenAPI** (a Kubernetes manifest, docker-compose): no completion, no code action and no problems. Opening or saving it clears any problems left over. Pinned in Task 1 (`parse` is `None`), Task 3 (`clears_problems_of_plain_yaml`) and Task 4 (`nothing_outside_openapi_files`).
2. **A `$ref` being typed**: `$ref: '#/comp` with no closing quote, or `$ref: ` with nothing after it, must still complete, and the replace range must cover only the value. Pinned in Task 2 (`an_unfinished_ref_ends_at_the_line_end`) and Task 4 (`completes_local_refs_inside_the_quotes`).
3. **Names with dots, slashes and braces** (`com.acme.Error`, `a/b` → `a~1b`, `#/paths/~1pets~1%7BpetId%7D/get`): they must resolve and complete. A dotted key path must not be split on `.`. Pinned in Task 2 (`resolves_json_pointers`, `offers_reusable_components_as_ref_targets`).
4. **Flow style** (`items: { $ref: … }`, `parameters: [{ $ref: … }]`): the refs are found, and the path-parameter check stays silent instead of reporting false positives. Pinned in Task 2 (`finds_refs_in_block_and_flow_style`) and Task 3 (`skips_the_parameter_check_when_parameters_cannot_be_read`).
5. **External refs**: `https://…` refs are skipped. Relative `../common.yaml#/X` resolves against the spec's directory. A missing file is an error. A missing pointer in an existing YAML file is an error. Pinned in Task 2 (`splits_file_and_fragment`), Task 3 (`reports_unresolved_local_and_file_refs`, `resolves_relative_paths`) and Task 4 (`goes_to_local_and_file_targets`).

## Scope

**In (v0.1.0):**

| Feature | How |
|---|---|
| Detect OpenAPI/Swagger documents | Top-level `openapi:` / `swagger:` key (`spec::parse`) |
| `$ref` completion | `completion` provider on `yaml`. Local pointers to reusable components (`#/components/<section>/<name>`; 2.0 `#/definitions|parameters|responses|securityDefinitions/<name>`). After `file.yaml#`, pointers into that file (its components, or its top-level keys when it is a fragment file) |
| `$ref` go to definition | `definition` provider: a local pointer, or a relative file and pointer (`read_file`) |
| Problems | On `file-opened` / `file-saved`: unresolved `$ref` (local, or relative YAML file and pointer), duplicate `operationId`, path template parameters that aren't declared (error) and declared `in: path` parameters missing from the template (warning) |
| Schema validation, key completion and hover | Code action "Add the OpenAPI schema for the YAML language server" inserts the modeline for the document's version. Covers missing required fields, wrong types and unknown keys |
| Endpoints tool window | `List` view: `METHOD /path` for every operation in the project's YAML specs. Activate → `open_location`. Refresh button |
| Preview | Web custom editor running Swagger UI 5.34.1 on the live document. Opens beside the text for `openapi.*`, `swagger.*`, `*.openapi.*` and `*.swagger.*` (yaml/yml/json); any other `.yaml`/`.yml`/`.json` through Open With › API Preview. Try it out disabled |
| HTTP client requests | Command "OpenAPI: Copy Requests for the HTTP Client": one `### …` block per operation, using the server URL and `{{param}}` variables, put on the clipboard |

**Dropped (and why):**

- **JSON specs for editing features.** `spring-text` scans block YAML only, and positions need a scanner. JSON specs are mostly generated, and the preview still covers them. Add a JSON scanner that produces the same `Key`s if users ask.
- **A JSON schema for JSON files.** There is no API to associate a schema with `vscode-json-language-server` (`crates/ide-tools/src/registry.rs` and `languages/json.toml` pass no schema settings). A `"$schema"` key is invalid at the root of an OpenAPI 3.1 document.
- **Hand-written "missing required field" checks.** The schema modeline covers them through the YAML language server.
- **Completion of relative file names in `$ref`.** It would need `find_files`, which walks the project and won't fit the 50 ms provider budget.
- **Rename, find usages, hover.** These provider kinds don't exist (see LIMITATIONS.md, Symfony section).
- **Structure view.** `syntax-provider` outline only runs for languages the plugin owns, and `yaml` is built in. The endpoints view stands in for it.
- **Redoc preview.** One renderer is enough. Swagger UI was checked against the web-view CSP: its only `new Function` is in a `try`, and `localStorage` is touched only with `persistAuthorization`. Redoc's search worker likely needs a `blob:` worker, which `default-src 'none'` blocks (not verified).
- **External `$ref`s in the preview.** The page has no network and can't read project files, so a multi-file spec shows resolver errors for the other files. Workaround if asked: the plugin code reads the referenced files and posts them to the page.
- **Live problems while typing.** There is no `document-changed` event: problems refresh on open and save.
- **AsyncAPI, code generation (OpenAPI Generator), structural diff, remote specs / SwaggerHub, URL completion inside `.http` files.** Each is a separate feature with no core value for v0.1. URL completion would need a project scan within 50 ms.

**Interfaces:**
- Consumes: `Key`, `parse`, `PETSTORE` (Task 1).
- Produces (`src/spec.rs`):

  - `pub fn refs(text: &str) -> Vec<Ref>`: a text scan, in document order.   - `pub fn target<'k>(keys: &'k [Key], fragment: &str) -> Option<&'k Key>`: resolves a JSON pointer (`/a/b~1c`). Callers treat an empty fragment as "the file itself".
  - `pub fn ref_targets(text: &str, keys: &[Key]) -> Vec<String>`: pointers (`#/…`), in document order.

- [ ] **Step 3: Implement**

`target` walks the pointer one segment at a time:
- Decode each segment: `%XX` percent escapes, then `~1` → `/`, then `~0` → `~`.
- Extend the current path with the segment: the candidate is `seg` at the start, `{cur}.{seg}` after that. When the segment is all digits and the first candidate doesn't exist, try `{cur}[{seg}]`.
- A candidate exists when some key equals it or starts with it followed by `.` or `[`. Sequence items have no key of their own.
- Return the first key (in document order) that equals the final path or starts with it followed by `.` or `[`.

`ref_targets` checks every key with segment `s = &text[k.at..k.end]` and `parent = k.key` minus the suffix `.{s}`. Its pointer is `#/` + `parent` with `.` → `/` + `/` + `s` escaped (`~` → `~0`, `/` → `~1`) when:
- `parent` starts with `components.` and has no other `.` (component names may contain dots; section names don't), or
- `parent` is `definitions`, `parameters`, `responses` or `securityDefinitions` (Swagger 2.0).

When there are no top-level `openapi`/`swagger` keys (a fragment file), every top-level key (a key with no `.` and no `[`) is a target too: `#/` + its escaped segment.

### Task 6: Copy requests for the HTTP client

**Files:**
- Create: `plugins/openapi/src/http.rs`

**Interfaces:**

- Produces:

    - 3.x: `servers[0].url`; a relative URL gets `http://localhost` in front;

    - `Err(Error::Denied(_))` → notify Warning `"OpenAPI"`, `"Allow the clipboard for OpenAPI in Settings › Plugins to copy requests."` (same pattern as `plugins/jpa-assist/src/lib.rs:52`).

- The dark theme is a colour inversion.

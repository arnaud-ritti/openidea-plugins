# Quarkus Tools (`aritti.quarkus`) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An OpenIDEA plugin that gives Quarkus projects key/value completion and warnings in their configuration files, Quarkus Dev Mode run configurations and a shortcut to code.quarkus.io.

**Architecture:** This is a text-based source port, not a language-server port. The Spring Boot plugin's metadata catalog and its properties/YAML completion engine move into `crates/spring-text` as `spring_text::metadata`, which learns MicroProfile `%profile.` prefixes. The Quarkus plugin feeds that engine two sources: a TSV generated from Quarkus 3.40.1's `quarkus-config-model.json` files (plus the original plugin's MicroProfile static metadata), and a text scan of the project's `@ConfigProperty` / `@ConfigMapping` Java declarations. Run detectors and the code.quarkus.io command are manifest entries plus one `host::open_url`.

**Tech Stack:** Rust (edition 2024, `wasm32-wasip2`), `openidea-plugin` SDK `v0.1.37`, `crates/spring-text` (path dependency), Python 3 (generator script, stdlib only).

**Spec:** the *Scope* section below (there is no separate spec document).

## Scope

**Porting path: source port.** The original is Quarkus Tools by Red Hat, Marketplace id 13234, `com.redhat.devtools.intellij.quarkus`. It is `FREE`, under EPL-2.0 (checked with `gh api repos/redhat-developer/intellij-quarkus/license`), and its source is public. This plan ports from Marketplace version 2.6.1, tag `2.6.1`, commit `be058542ce55eda5a72d3b35a205d3027e8a906f`, and records that revision in `change-notes`. The original has no NOTICE file. Quarkus itself (the data source) is Apache-2.0 and ships only `META-INF/LICENSE`, no NOTICE.

**Why text-based and not the language servers.** The original embeds LSP4MP/quarkus-ls and qute-ls through LSP4IJ. Those servers get every project fact (the properties of the classpath, `@ConfigProperty` declarations, Qute data models) by sending requests to the client: `microprofile/projectInfo`, `microprofile/propertyDefinition`, `qute/template/project`. IntelliJ answers them with the plugin's PSI code, and VS Code with a jdtls extension bundle. OpenIDEA can do neither:

- Its LSP client answers any server request it doesn't know with `METHOD_NOT_FOUND` (`crates/ide-lsp/src/handler.rs:274-310`).
- jdtls bundles are hard-wired to java-debug, the usages bundle and the Kotlin bridge (`crates/ide-host/src/project.rs:195-198`), so a plugin can't add `com.redhat.microprofile.jdt.core`.
- Plugin `languages` can't take over the built-in `properties`, `yaml` or `html` ids (reference §6), so a plugin couldn't even attach a server to those files.

Without `projectInfo`, quarkus-ls offers no property completion. The language-server route would ship a JVM server that does nothing.

**Features in:**

1. **Completion** in `application*.properties`, `application*.yaml|yml` and `META-INF/microprofile-config.properties` of Quarkus modules:
   - full keys in `.properties`, the next segment in YAML;
   - the type as detail, and documentation with the description, the default and any deprecation;
   - values for enums, booleans and log levels.

   Keys come from Quarkus 3.40.1's metadata for 42 extensions (2128 keys) and from the MicroProfile static metadata of the original plugin.
2. **Profiles:** `%dev.`, `%test.` and `%prod.` are offered at the start of a key. Profiled keys (`%dev.quarkus.http.port`, and YAML under `"%dev":`) complete and are checked as their base key.
3. **Project keys:** `@ConfigProperty(name, defaultValue)` on fields and parameters. `@ConfigMapping(prefix)` interfaces, with `@WithName`, `@WithParentName`, `@WithDefault`, `namingStrategy` (kebab, verbatim, snake), `Optional<T>` unwrapping and nested interfaces declared in the same file. This ports `MicroProfileConfigPropertyProvider` and `QuarkusConfigMappingProvider`.
4. **Warnings:** deprecated keys, and unknown keys inside a known group of two or more segments.
5. **Run detectors:** Quarkus Dev Mode with `mvn quarkus:dev`, `gradle quarkusDev` and `quarkus dev`.
6. **Command:** *Quarkus: Open code.quarkus.io*.

**Features dropped, and why:**

- **Java-side MicroProfile/Quarkus LS features:** hover, go-to-definition, code lens, inlay hints, JAX-RS workspace symbols, Java diagnostics and quick fixes (`@ConfigProperty`, `@Startup` health checks, REST client, GraphQL). There is no Java semantic model, and no hover, inlay or code-lens provider kinds.
- **Qute** (language, completion, validation, debugger). Templates are `.html`, `.txt` or `.json` files under `templates/`, and a plugin can't substitute their language. qute-ls needs the JDT side too.
- **In-IDE project wizard:** no new-project API and no file creation. The browser opens code.quarkus.io, which is itself the form, so a `Form` view like `plugins/spring-initializr` would only duplicate it.
- **Debugger auto-attach to dev mode (port 5005) and the run dashboard:** no debugger API, and run detectors have a fixed command.
- **`./mvnw` / `./gradlew`:** a `process:` program must be on `PATH` or absolute. Project-relative paths are refused (`crates/ide-extension/src/capability.rs:156`, `ledger.rs:311-333`).
- **Named-map entries** (`quarkus.datasource."name".*`, `quarkus.log.category."cat".level`): the metadata spells them with quoted placeholders, and the shared catalog has no wildcard segments. They are dropped from completion but never flagged.
- **Extensions outside the curated 42, and metadata from dependency jars:** the classpath and jars can't be read. The generator takes extra artifact ids.
- **Value type validation:** MicroProfile converters are lenient, so it would mostly add noise for v0.1.
- **Settings pages, facets, icon provider, implicit-usage provider, class-name completion remover, Roq, Renarde, Web Bundler:** nothing to configure, no equivalent, or out of the core.

The list: `quarkus-core quarkus-arc quarkus-vertx quarkus-vertx-http quarkus-rest quarkus-rest-jackson quarkus-rest-client quarkus-jackson quarkus-hibernate-orm quarkus-hibernate-orm-panache quarkus-hibernate-validator quarkus-datasource quarkus-agroal quarkus-jdbc-postgresql quarkus-jdbc-mysql quarkus-jdbc-h2 quarkus-reactive-pg-client quarkus-flyway quarkus-liquibase quarkus-smallrye-health quarkus-smallrye-openapi quarkus-smallrye-fault-tolerance quarkus-smallrye-jwt quarkus-micrometer quarkus-opentelemetry quarkus-oidc quarkus-oidc-client quarkus-security quarkus-messaging-kafka quarkus-kafka-client quarkus-scheduler quarkus-cache quarkus-redis-client quarkus-mongodb-client quarkus-qute quarkus-mailer quarkus-grpc quarkus-websockets-next quarkus-container-image-jib quarkus-kubernetes quarkus-logging-json quarkus-config-yaml`. All 42, and their `-deployment` jars, exist at 3.40.1.
- For each artifact and `<artifact>-deployment`: fetch `https://repo1.maven.org/maven2/io/quarkus/<a>/<v>/<a>-<v>.jar`. Skip it with a note on stderr on HTTP 404. Read `META-INF/quarkus-config-doc/quarkus-config-model.json` and `quarkus-config-javadoc.json` (`elements`).
- Walk `configRoots[].items` recursively. Sections have `items` too, so always recurse. An item is a property when its `@class` ends with `ConfigProperty`.
- The name is `path.property`; `additionalPaths` are ignored. If the name contains `"`:
  - when the item has `map: true` and its only quoted segment is the last one, keep the name before `."`;
  - otherwise drop it, with `# ponytail: named-map entries need wildcard segments in spring_text::metadata`.
- Type: `typeDescription`, falling back to the simple name of `type`. Default: `defaultValue`. Deprecation: `w:<replacement>` when `deprecation` is present (the replacement is usually empty).
- Description: `elements["<sourceType>.<sourceElementName>"].description`, cut at the first `<p>` or javadoc block tag (`@deprecated`, `@see`…). `{@code x}` and `{@link x}` become `x`, HTML tags are removed, then keep the first sentence, at most 110 characters, as in spring-boot.
- Hints: `enumAcceptedValues.values[*].configValue` gives `@<name>\tv…`. Properties whose type is `Level` get the values of the `java.util.logging.Level` hint in the original's `jboss-logmanager-metadata.json`.
- MicroProfile: merge `properties` and `hints` of `mp-config`, `mp-context-propagation`, `mp-graphql`, `mp-health`, `mp-jwt`, `mp-lra`, `mp-metrics`, `mp-openapi` and `mp-opentracing` `-metadata.json`, from `https://raw.githubusercontent.com/redhat-developer/intellij-quarkus/be058542ce55eda5a72d3b35a205d3027e8a906f/src/main/resources/static-properties/<file>`. Types are reduced to simple names (`java.lang.String` → `String`).
- First name wins. Output is sorted: properties, then hints. Header line: `# Quarkus <v> configuration metadata (Apache-2.0) and MicroProfile metadata from Quarkus Tools for IntelliJ 2.6.1 (EPL-2.0), see NOTICE`. At the end, print `<n> properties, <m> hints` to stdout.

# F Gap Rows of the PHP Ecosystem Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the F part of the gap rows the audit classed feasible for `symfony` (19 rows), `laravel` (Laravel Idea 8 rows, free Laravel plugin 1 row) and Blade (1 row): text inspections, caret code actions, templates, completion and a status item, each re-checked against the code and the API facts.

**Architecture:** Every task adds text-based checks or contributions to an existing plugin: `publish_diagnostics` on `file-opened`/`file-saved`, `code-actions` providers (they receive the selection), `completion` providers, `fileTemplates`, `fileIcons`, one status item. No new API, no new crate, no new dependency. New checks live in new small modules next to `checks.rs` (Symfony) and `eloquent_checks.rs` (Laravel) and return the plugin's `Finding` type. Tasks are independent except where a task lists a dependency.

**Tech Stack:** Rust (`wasm32-wasip2`), `openidea-plugin` SDK 0.1.37 (`openidea:plugin@1.1.0`), `MockHost` tests, `CompletionItem.snippet` for Blade snippets.

**Spec:** [`docs/audit-gaps-2026-11-06.md`](../../audit-gaps-2026-11-06.md) (appendix: _Symfony Plugin_, _Blade_, _Laravel Idea_, _Laravel_ F rows), evidence in [`docs/audit-gaps-2026-11-06/C-php.md`](../../audit-gaps-2026-11-06/C-php.md), API limits in [`docs/audit-gaps-2026-11-06/api-facts.md`](../../audit-gaps-2026-11-06/api-facts.md). Style and shared task shape follow [`2026-11-06-feasible-parity.md`](2026-11-06-feasible-parity.md), whose Outcome section lists what earlier passes already built.

## Global Constraints

- Each plugin stays its own Cargo project; no root workspace; run cargo inside `plugins/<name>` with `export PATH="$HOME/.cargo/bin:$PATH"` (cargo is not on PATH by default).
- Quiet unless sure: a dynamic or interpolated name is invisible to every check, a name that may come from a library or bundle never warns, and every check has a quiet test (`<check>_is_quiet_for_library_or_dynamic_name` or a more specific `..._is_quiet_...`).
- Ranges use UTF-16 columns and CRLF files report correct lines: every new scanner gets `ranges_use_utf16_columns_with_multibyte_text` and `crlf_files_report_correct_lines` (or a group-prefixed variant).
- A fixed file publishes an empty list: every check group gets `fixed_file_publishes_empty_list` (a file that had problems, rewritten without them and saved, publishes `[]`).
- One settings boolean per check group (default on) in the plugin's `settings.schema.json`; a switched-off group publishes nothing. A rewrite or code action is not a check group and needs no setting.
- `events` is an `optional` capability: `activate` subscribes to `file-opened` and `file-saved`, and on denial logs `LogLevel::Warn` and still activates (pattern: `plugins/blade/src/lib.rs`, test `denied_events_log_a_warning_and_still_activate`). Every event-driven plugin needs an `activation` entry in `plugin.toml` (Symfony: `on-language:*`, Laravel: `on-language:php`, `on-language:blade`; keep them).
- Providers have a 50 ms budget: scan in events and commands, cache in the index, never walk the project from a provider. Code actions may re-run the single-file checks of the open document.
- `find_files` skips hidden and ignored paths on the real host and the mock does not: read explicit paths with `read_file` (for example `ide-blade.json`). A missing file is `Invalid` on the host and `NotFound` in the mock: treat both as absent (test `missing_file_is_treated_as_absent`, both error kinds).
- Code actions edit existing files only (`fileTemplates` are the way to add new files); several edits in one file are allowed. No popups or input dialogs: a choice becomes one code action per option. A command's returned text is dropped: use `host::notify`. Settings are scalar types only (lists are comma-separated strings).
- No caret control, rename, references, hover, injection, streaming or decorations. Anything needing PHP types (U4) is out of this plan (see Rulings).
- Per plugin finish with `cargo test` (no new warnings) and `openidea-plugin build` (runs `check`); no errors.
- Never hand-edit `version` in `plugin.toml` (release-please). Conventional commits `feat(<plugin>): ...` / `fix(<plugin>): ...`; the message ends with the line `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`. Do not touch `.env`.
- Implementers do not edit `PARITY.md` or `LIMITATIONS.md`; they write a "Doc notes" paragraph in their report (new codes, limits, unverified IDE behaviour) and update only the plugin's own README.
- Licence: `symfony` (Symfony Plugin 2026.2.314, revision `b6c1034f6669784d7a58de7535515b7da93db87e`, MIT) and the free Laravel plugin (0.15.4, revision `3a07f4a5f67dc0aacbcd6fdb11a8b5c9814803b0`, MIT) are source ports: keep `LICENSE`/`NOTICE`. Where this plan says "public source", the implementer may read that class in the MIT repository (the rules are quoted in the task). Checks the public source lacks (marked **paid original**) are written from the Symfony, Doctrine and Twig documentation: write your own messages and thresholds. Laravel Idea and Blade originals are proprietary: public documentation only, never copy vendor text, do not open decompiled code of them (the audit saw intention and inspection names, not their rules; the rules below are this plan's own, from Laravel's documentation).
- New PHP/Twig/YAML scans skip comments (`//`, `#`, `/* */`, `{# #}`, `{% verbatim %}` bodies) and string contents unless the check is about a string.

## Review Focus

Failure modes the audit implies and no happy path exercises; each line has its test in the owning task.

- **Twig comments and verbatim bodies:** `{# path('x') #}` or a verbatim body containing `{% for a in b if c %}` must not report. Tests `twig_checks_ignore_comments_and_verbatim` (Task 2).
- **Short-name clashes and repeated edits:** adding a `use` line when another class with the same short name is imported must not produce a broken file, and applying a rewrite twice must not duplicate imports. Tests `insert_use_refuses_a_short_name_clash` (Task 1), `rule_object_is_not_offered_when_another_rule_class_is_imported`, `root_facade_import_is_quiet_when_the_name_is_imported_elsewhere` (Task 10).
- **Version gates:** a deprecation that only exists from Symfony 6.4 or 8.1 must stay quiet when `composer.json` names an older framework or none. Tests `route_attribute_namespace_is_quiet_below_6_4`, `<deprecation>_is_quiet_below_the_gate` (Task 7).
- **Mapping variants:** the same Doctrine mistake in a PHP attribute, an XML file and a YAML file must be found in each, and an attribute written through an alias (`use Doctrine\ORM\Mapping as Orm`) or an unrelated class named `Table`/`Column` must behave. Tests `doctrine_alias_import_is_followed`, `doctrine_checks_are_quiet_without_the_orm_mapping_import` (Task 8).
- **Hidden config files:** `ide-blade.json` and `.idea/ide-blade.json` are read by path; a malformed or empty JSON must index nothing and not fail the index. Tests `ide_blade_json_malformed_is_ignored`, `ide_blade_json_in_a_hidden_directory_is_read` (Task 11).

## Rulings (rows downgraded, no task planned)

Re-checked against the code and `api-facts.md`. Rows are groups: only the F part is built.

- **Symfony row "Inspection, TwigAssetsTagMissing" (part of the 4-inspection row):** downgraded. The tag is the removed Assetic syntax (`{% javascripts %}`, `{% stylesheets %}`); its inputs resolve against bundle directories and named assets the index cannot see (only `public/` is indexed), so any report is a false-positive risk and the syntax is dead. The other three inspections of the row (`TwigForConditionDeprecated`, `TwigComponentMixedSyntax`, `TwigComponentSelfMacroImport`) are built in Task 2.
- **Symfony row "Status bar widget, file icons, icon provider, editor notification":** the editor notification part is downgraded (no editor banner API; `host::notify` toasts are not an editor notification). Status item and file icons are built in Task 5. The icon is a new own-drawn glyph, not the Symfony logo.
- **Symfony intention `AddRouteAttributeIntention`:** built without the original's caret move to the path (no caret control) and with the controller test done textually (name ends `Controller` or extends `AbstractController`/`Controller`); the original asks the index whether the `Route` class exists, ours reads the `symfony/framework-bundle` constraint (6.2 or newer).
- **Symfony intentions `RouteActionParameterIntention`, `CommandInvokeParameterIntention`:** built as one code action per parameter type (the original opens a chooser popup, U5). Parameters already present are detected by simple or fully qualified type name in the signature text only.
- **Symfony row "Settings (7 configurables)":** only the F part that is not already there: `compiledContainers`, `compiledRoutes`, `publicDirectory` exist; the remaining configurable with a scalar form is the extra Twig namespaces (Task 6). The rest (templates root, translation directories, route files as lists) has no behaviour in our index to configure.
- **Symfony quick-fix row "typo suggestions on Done checks":** not in the appendix list of F rows; left out. "Create template" is U2 (B).
- **Symfony file templates beyond the container files** (command variants, `controller_annotations`, `twig_extension_function_attribute`): not in the 19-row list; left out (annotations are deprecated style).
- **Laravel Idea row "Other: settings":** only the part that changes behaviour in this plan: `controllersNamespace` (Task 10) plus one boolean per new check group. The 17 + 6 configurables of the original have no counterpart in our index.
- **Laravel Idea row `ConvertCssClassesToClassDirectiveCall`, `WrapCssClassesWithClassDirectiveCall`:** the audit did not describe the second one. This plan defines them as: convert a static `class="a b"` to `@class(['a', 'b'])`, and wrap a `class` value that mixes classes with `{{ expr }}` echoes into `@class([...])` with the echoes as expression items. Anything else (conditional `@if` inside the value, `{!! !!}`) is not offered.
- **Laravel Idea rows `ConvertRuleCallFromStringToObject`, `ConvertRootFacadeCall`:** kept after the re-check (static tables from Laravel's documentation, no type resolution). Limited to the rules `exists`, `unique` (at most two arguments), `in`, `not_in` and to the core facade aliases of the facade reference; custom facades and project rules are never touched.
- **Blade row "completion.contributor, weigher, htmlInText completion":** only the F part: snippet directive completion with arguments. It lives in `aritti.laravel` (it already owns the `blade` completion provider; adding a second `blade` provider to `aritti.blade` would answer twice). `aritti.blade` is not touched. Weigher and `htmlInText` completion are not built.
- **Free Laravel plugin row "Template path configuration, `ide-blade.json` namespaces":** built for `namespaces[]` entries (`namespace`, `path`) in `ide-blade.json` at the project root and in `.idea/`; the original finds the file anywhere in the project, which needs `find_files` through hidden paths.
- **Not F, not planned (stay F\* or B):** anything in the audit tables that needs the receiver type (QueryBuilder deprecations, `DoctrineMappingArrayAccessDeprecation`, `AutowireWrongClass`), file creation, popups, rename or references.

Rules (pinned):
- `twig-route-compare`: a string literal compared with `app.request.attributes.get('_route')` or `app.current_route` through `==`, `!=`, `is same as('x')`, `in [...]` or `not in [...]` (every literal of the list; `starts with` is excluded, a literal followed by `~` or an interpolation is dynamic). Reported on the literal contents when `index.compiled_routes` and the name is not `_`-prefixed and not in `index.routes`.
- `twig-for-condition`: `{% for ... in ... if cond %}` where `if` sits outside quotes and brackets in the tag head; range is the `if` word. An `{% if %}` inside the body is not a for condition.
- `twig-component-block-syntax`: a `{% block %}` tag inside an open `<twig:Name ...>` element (not `<twig:block>`, self-closing elements do not open); range is the word `block`. A scanner that finds an unbalanced element stays quiet for the rest of the file.
- `twig-component-self-import`: `_self` as the source of `{% from _self import ... %}` or `{% import _self as x %}` inside an open `<twig:Name>` element or between `{% component 'Name' %}` and `{% endcomponent %}`; range is `_self`.
- `twig-missing-translation-domain`: the domain of `'k'|trans(args, 'domain')` (second positional argument or `domain:` named argument) with the PHP check's exceptions (only lowercase project-style names, built-in domains, `+intl-icu` suffix).
